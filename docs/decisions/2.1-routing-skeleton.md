## Decisions

### D1 — Route group and layout structure
- **Context:** The app requires clean separation between unauthenticated flows (sign-in, sign-up) and authenticated features (month overview, tabs, line details, modals) without url pollution.
- **Options considered:**
  - A) *Flat route hierarchy (`/sign-in`, `/sign-up`, `/overview`, `/settings`):* Leaks route naming into URLs and makes nested modal/tab management messy.
  - B) *Route groups `(auth)` and `(app)` with nested `(tabs)`:* Expo Router ignores parenthesis groups in URLs (`/(auth)/sign-in` resolves as `/sign-in`), cleanly scoping headers and layouts.
- **Chosen:** Option B.
- **Why:** Exactly matches the route map defined in `docs/ARCHITECTURE.md`. The root layout simply renders the root stack, while `app/index.tsx` redirects unconditionally to `(app)/(tabs)` until the auth gate arrives in Step 3.3.
- **Trade-offs accepted:** Requires distinct `_layout.tsx` files for each group.
- **Revisit when:** Deep linking requirements introduce nested subdomain routing.

### D2 — Modal presentation configuration
- **Context:** `add-transaction` and `new-month` must appear as native slide-up modals above the current tab context.
- **Options considered:**
  - A) *Inside `(tabs)`:* Causes modals to render inside the tab frame, maintaining the bottom tab bar visible underneath.
  - B) *At `(app)` Stack level with `options={{ presentation: "modal" }}`:* Slides up over the tab bar on iOS and uses native modal behavior on Android.
- **Chosen:** Option B.
- **Why:** Standard native UX convention on iOS/Android; covers the tab bar and allows clean dismissal via `router.back()`.
- **Trade-offs accepted:** Navigation to modals must route through `/(app)/add-transaction` or `/add-transaction`.
- **Revisit when:** A full-screen form with custom navigation bar is required.

### D3 — Param handling and typing
- **Context:** `useLocalSearchParams` is used to read `year`/`month` on the overview tab, `[id]` on line details, and `lineId` on transaction modals.
- **Options considered:**
  - A) *Global state / React context for current month:* Detaches URL from app state, breaking deep linking and web navigation.
  - B) *URL parameters as single source of truth:* The overview reads `params.year` and `params.month`, falling back to local calendar values when absent.
- **Chosen:** Option B.
- **Why:** Mandated by `docs/ARCHITECTURE.md` ("URL/params are the source of truth for the selected month: `?year=2026&month=10`"). Ensures bookmarks and deep links restore the exact viewing period.
- **Trade-offs accepted:** Parameters from `useLocalSearchParams` are string-typed and require validation/fallback in consuming components.
- **Revisit when:** Custom hook `useMonthParams` is built in Step 4.2.

### D4 — Enabling typed routes
- **Context:** Type-safe route navigation prevents broken links and typos at compile time.
- **Options considered:**
  - A) *Manual route path strings:* Error-prone with no autocomplete or compile checks.
  - B) *Expo Router typed routes:* Enabled via `"experiments": { "typedRoutes": true }` in `app.json`.
- **Chosen:** Option B.
- **Why:** First-class Expo Router feature that generates `.expo/types/router.d.ts` typing all `router.push`, `router.replace`, and `<Link>` paths.
- **Trade-offs accepted:** Marked as experimental in Expo SDK configuration, but fully stable in Expo SDK 50+.
- **Revisit when:** Expo moves typed routes out of the `experiments` flag into top-level config.

### D5 — Deviations from planned route map
- **Context:** Audit the built skeleton against `docs/ARCHITECTURE.md`.
- **Finding:** No deviations. All routes (`_layout.tsx`, `(auth)/sign-in`, `(auth)/sign-up`, `(app)/(tabs)/index`, `(app)/(tabs)/categories`, `(app)/(tabs)/settings`, `(app)/line/[id]`, `(app)/add-transaction`, `(app)/new-month`) match the plan exactly.
